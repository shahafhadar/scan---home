# חיווט האב-טיפוס (מסלול A)

הכל על ה-ESP32-S3-DevKitC-1 שכבר אצלך, על פרפורד, עם הרכיבים מ-[`bom-prototype.csv`](bom-prototype.csv).
מפת הפינים זהה למוצר ([README §5](README.md#5-מפת-פינים-זהה-ב-a-וב-b)).

**הסדר:** כל שלב מסתיים בבדיקה, כמו ב-`docs/hardware-setup.md`, כדי שלעולם לא ננפה שני דברים במקביל.

**כלים:**
- מלחם עם חוד דק.
- פינצטה, או מלחם אוויר חם, ל-R24.
- מודד עם תחום µA.
- פס דבק Kapton.

> ⚠️ **לפני הכל:** בודקים קוטביות של הסוללה במודד. JST-PH הפוך נפוץ בסוללות סיניות.
> הפין שמסומן `+` ליד שקע `BATT` של לוח Adafruit חייב לקבל את החוט האדום, וזה חייב להיות ה-+ במודד.
> חיבור הפוך יכול להרוס את המטען.

## שלב 0: הסרת R24 ב-DevKit

**למה:** בשרטוט הרשמי (v1.0 ו-v1.1) יש שני פסי 3.3V:

| פס | מה מחובר אליו |
|---|---|
| `VCC_3V3` | ה-LDO ‏(SGM2212), נורית ההדלקה האדומה (דרך 5.1k), גשר ה-USB-UART ‏(CP2102N, ‏VDD ו-REGIN) ונורית ה-RGB ‏(SK68XXMINI-HS) |
| `ESP_3V3` | המודול, ה-RC של EN, ופיני `3V3` ‏(J1-1, ‏J1-2) |

**R24 (0Ω)** הוא החיבור היחיד בין שני הפסים. כשמסירים אותו, הסוללה מזינה רק את המודול.

**איך:**

1. **הלוח מנותק מכל מקור מתח.**
2. **איתור:**
   - מוצאים את ה-LDO: רכיב בעל 3 רגליים ליד שקעי ה-USB, עם לשונית רחבה.
   - שמים חוד אחד של המודד במצב צפצוף על `3V3` ‏(J1-1), והחוד השני על רגלי ה-LDO.
     אחת מהן מצפצפת: זו `VOUT`, כל עוד R24 במקום.
   - R24 הוא נגד קטן (0402/0603), מסומן `0` או בלי סימון, על המסלול בין ה-LDO למודול,
     בדרך כלל ליד פין ה-3V3 של המודול.
   - אישור: רגל אחת שלו מצפצפת ל-J1-1, והשנייה ל-VOUT של ה-LDO.
3. **הסרה:** מחממים את שני הצדדים (שני מלחמים, פינצטה מחממת או אוויר חם), ומרימים.
4. **שומרים את הנגד בשקית.** אפשר להחזיר אותו, או לגשר בבדיל.

**בדיקה:**

| בין | צפוי |
|---|---|
| J1-1 (3V3) ↔ ‏VOUT של ה-LDO | **פתוח** (אין צפצוף) |
| J1-1 ↔ ‏GND | **אין קצר** (יותר מכמה kΩ, הקבלים נטענים) |
| J1-1 ↔ פין 3V3 של המודול | **צפצוף** |

**אם אין R24 בלוח שלך** (לוח תואם, או גרסה שונה): **לא חותכים מסלולים.** ממשיכים בלי השלב הזה.
האב-טיפוס יעבוד, אבל בשינה ימשוך ~1–2mA (‏README §7.2). זה מספיק לבדיקת פונקציונליות, לא למדידת חיי סוללה.

**מה משתנה אחרי ההסרה:**
- **שקעי ה-USB של ה-DevKit מזינים רק את צד הגשר.** כדי לצרוב, מחברים גם את הסוללה או USB-C ללוח Adafruit.
- **הצריבה עובדת מאותו שקע `UART` כמו היום.** האדמה משותפת, שני הצדדים ב-3.3V, וטרנזיסטורי ה-auto-program מושכים
  את EN ו-GPIO0 בצד המודול.
- **צריבה דרך שקע ה-`USB` הטבעי (GPIO19/20) עובדת גם היא.**
- **נורית ה-RGB שעל הלוח לא תידלק יותר.** לכן יש LED RGB חיצוני.

## שלב 2: ה-DevKit עולה מהסוללה

1. מלחימים פס נקבה 1×22 לכל צד (J1, ‏J3), במרחק שמתאים ל-DevKit. מכניסים את ה-DevKit.
2. קצה האנטנה של המודול **בולט מעבר לשפת הפרפורד.** אין חוטים או נחושת מתחתיו.
3. פין `5V` ‏(J1-21) **לא מחובר.** כדאי לכופף את השקע שלו החוצה או לבודד בקפטון.

### בדיקה 2

1. רק סוללה, בלי USB בכלל. ה-DevKit עולה (הנורית שעליו **לא** נדלקת, וזה תקין).
2. מחברים USB לשקע `UART` של ה-DevKit, **כשהסוללה מחוברת:**
   ```bash
   cd firmware && ./dev.sh flash uart
   ```
   הטרמינל מדפיס את שורת הפתיחה ואת המספר הסידורי, כמו בשלב 3 של `hardware-setup.md`.
3. מנתקים את ה-USB. המכשיר ממשיך לרוץ מהסוללה, וזה מוכיח שההזנה עובדת.

## שלב 3: מנוע הסריקה

### 3א. ווסת מנוע U2 (RT9080 #2)

| מ | אל | דרך | הערה |
|---|---|---|---|
| `VSYS` | U2 פין 1 (VIN) | | 10µF לאדמה צמוד. **מ-VSYS, לא מה-3V3** |
| U2 פין 2 | GND | | |
| GPIO9 ‏(J1-15) | U2 פין 3 (EN) | 1kΩ | |
| U2 פין 3 (EN) | GND | 100kΩ | כבוי כשהפין צף (בשינה) |
| U2 פין 3 (EN) | `3V3` | **JP1** (גשר) | לבדיקה עם הקושחה הנוכחית: מנוע תמיד דלוק |
| U2 פין 5 (VOUT) | `3V3_ENG` → GM861S VCC | | 10µF + 100nF **צמודים למחבר המנוע** |

### 3ב. GM861S

**הממשק:** מחבר SH1.0 6 פינים.

**הסדר הפיזי לאורך המחבר:** `VCC – TXD – RXD – GND – D− – D+`.
- ב-GM861S פין 1 = D+ ופין 6 = VCC.
- ב-GM861 הגדול המספור הפוך.

**מזהים את VCC במודד מול השרטוט שבמדריך המנוע, לפני שמחברים מתח.**
צבעי החוטים בכבל לא מעידים על הסדר (המדריך אומר זאת במפורש).

| פין מנוע | אל | דרך | הערה |
|---|---|---|---|
| VCC | `3V3_ENG` (U2 VOUT) | | אסור פחות מ-3.1V |
| GND | GND | | |
| TXD | GPIO17 ‏(J1-10) | 1kΩ | מגביל הזנה לאחור כשהמנוע כבוי |
| RXD | GPIO18 ‏(J1-11) | 1kΩ | |
| D−, D+ | לא מחוברים | | לבודד בקפטון |

> **אסור לחבר או לנתק את כבל המנוע כשיש מתח** (הוראת היצרן).
> אחרי כיבוי מחכים לפחות **2 שניות** לפני הדלקה חוזרת.

### בדיקה 3: סריקה אמיתית, עם הקושחה של היום

1. **JP1 מחובר.** המנוע מוזן קבוע, ונורית התאורה שלו נדלקת. ברירת המחדל שלו היא *Continuous Mode*:
   הוא סורק כל מה שמולו, ב-9600 8N1, עם `CR` בסוף.
2. הקושחה מ-בדיקה 2 (`uart`) כבר קוראת UART על 17/18 ב-9600.
3. מכוונים למוצר מהמטבח. **הפריט מופיע בטלפון.**

אם זה עובד, הוכחנו את:
- המנוע.
- החיווט.
- ההזנה מהסוללה.
- השרשרת עד השרת.

כל זה בלי שורת קושחה חדשה.

**זרמים למדידה ב-JP2:** סרק עם המנוע דלוק; בזמן סריקה; בזמן שליחה ב-WiFi.
רושמים אותם לעדכון התקציב.

> במצב Continuous אותו ברקוד יכול להיקרא שוב ושוב. `SCAN_DEBOUNCE_MS` מסנן רק 500ms.
> זה מצב בדיקה בלבד. הקושחה החדשה תעביר את המנוע ל-Command Triggered Mode.

## שלב 7: מדידת זרם שינה (אחרי קושחת השינה)

**למה בשני שלבים:** מד µA בטור מוסיף "burden voltage". בפולס WiFi של 350mA זה יכול להפיל את הבקר.

1. JP2 מחובר. המכשיר ער ושולח.
2. **אחרי** שהוא נרדם, מחברים את המד (תחום µA) על שני פיני JP2 ורק אז מוציאים את הגשר.
3. קוראים: **יעד ~10–13µA** במדידה הזו: ESP ‏~8, ‏U1 ‏2–4, ‏U2 ‏0.1.
   ה-bq24074 (‏4.3µA) והמחלק (‏2µA) נמצאים לפני JP2 ולא נמדדים כאן.
4. מחזירים את הגשר **לפני** שלוחצים על ההדק.

| מה רואים | מה זה בדרך כלל |
|---|---|
| ~1–2mA | R24 עדיין במקום, או שהלוח לא רשמי (שלב 0) |
| ~6mA | המנוע מוזן: JP1 מחובר, או ש-EN צף בלי ה-100k |
| מאות µA | WiFi לא נכבה, או טרנזיסטור דרייבר צף |
| 20–40µA | פול-אפ פנימי דלוק, או RTC periph דלוק. בעיית קושחה |

## מכני

- **החזקה:** ה-DevKit יושב בשקעים בלבד, אין לו חורי הרכבה. הפרפורד ולוח Adafruit על ספייסרי ניילון M2.5/M3.
- **ממדים:** קופסה מודפסת של ~110×70×40mm. הסוללה מתחת לפרפורד, בצד הרחוק מהאנטנה.
- **המנוע:** בקדמת הקופסה, מאחורי חלון אקריליק שקוף של 1.5–2mm. לא חוסמים את חרוט 81° מול העדשה.
- **בדיקות:** נקודות בדיקה מפס זכר על `VSYS`, ‏`3V3`, ‏`3V3_ENG`, ‏GND.
- **חיבורים:** חוטי סיליקון קצרים. לחבר הזנה (VSYS/GND) בחוט עבה יותר מאשר אותות.
