# הקמת המוצר — מדריך שלב אחר שלב

מהקופסה עד סריקה אמיתית שמופיעה בטלפון. חמישה שלבים, כל אחד מסתיים בבדיקה
שאומרת בוודאות אם הוא עבד — כדי שלעולם לא תנפה שני דברים במקביל.

---

## שלב 1 — השרת נגיש

השרת הוא אפליקציית scan-home ב־Vercel, ולא צריך להריץ אותו על המחשב.
הקושחה מצביעה כברירת מחדל על סביבת הפיתוח (develop).

**בדיקה:** פתח בטלפון את https://scan-home-git-develop-shahaf-hadars-projects.vercel.app
והתחבר עם המייל. סביבת הפיתוח נעולה בהגנת Vercel, ולכן המכשיר צריך את מפתח
העקיפה (Protection Bypass for Automation, בהגדרות הפרויקט ב־Vercel):

```bash
cd firmware
export VERCEL_BYPASS=<המפתח>
```

---

## שלב 2 — התקנת PlatformIO

ה-Python של Homebrew חוסם התקנות גלובליות, אז PlatformIO מותקן בתוך הפרויקט.
זה קורה לבד בפעם הראשונה:

```bash
cd firmware && ./dev.sh pio --version
```

צריך להדפיס `PlatformIO Core, version 6.1.19` או חדש יותר. ההתקנה לוקחת
כדקה, פעם אחת.

**אל תריץ `pip install platformio` ישירות** — הוא ייכשל עם
`externally-managed-environment`. זו לא תקלה אצלך, ככה Homebrew מוגדר.

מכאן והלאה כל פקודות ה-`pio` עוברות דרך `firmware/dev.sh pio`, ואין צורך להפעיל
venv ידנית.

## שלב 3 — צריבה ראשונה, בלי שום סורק

חבר את הלוח למחשב **בשקע המסומן `UART`** (יש שני שקעי USB-C; זה שקרוב לקצה
הלוח). שום חיווט אחר — לא באזר, לא דונגל, כלום.

```bash
cd firmware && ./dev.sh flash serial
```

זה כותב את כתובת המחשב לקובץ הגדרות, מקמפל, צורב ופותח טרמינל — הכל בפקודה
אחת. הצריבה הראשונה מורידה כ-300MB של toolchain; אחר כך זה לוקח 10 שניות.

**מה שאמור לקרות:** הטרמינל מדפיס `ScanCart 1.0.0 (serial (bring-up) scanner)`
ואת המספר הסידורי, והנורית שעל הלוח מהבהבת בכחול.

הבהוב כחול = המכשיר מחכה שיגדירו לו WiFi. זה השלב הבא.

---

## שלב 4 — חיבור ל-WiFi ושיוך לחשבון

1. **בטלפון**, פתח את רשימת רשתות ה-WiFi. תופיע רשת בשם `ScanCart-XXXX`.
   התחבר אליה.
2. עמוד ההגדרה אמור להיפתח מעצמו. אם לא — גלוש לכתובת `192.168.4.1`.
3. בחר את רשת הבית שלך והזן סיסמה. **רק רשתות 2.4GHz מוצגות** — זה מכוון.
4. העמוד יציג **קוד בן שש ספרות**. רשום אותו.
5. הנורית עוברת לסגול נושם = מחובר לאינטרנט, מחכה לשיוך.
6. פתח את האפליקציה בטלפון, היכנס לחשבון, לשונית **מכשירים**, הקלד את הקוד.
7. **שלושה צלילים עולים** והנורית ירוקה. המכשיר משויך.

**בדיקה:** בלשונית מכשירים המכשיר מופיע עם נקודה ירוקה.

## שלב 5 — הסריקה הראשונה

בטרמינל שעדיין פתוח, הקלד ברקוד ולחץ Enter:

```
7290000066318
```

התשובה אמורה להיות:

```
[scan] 7290000066318 -> חלב תנובה 3% בקרטון 1 ליטר
```

**ופתח את האפליקציה בטלפון — הפריט שם, בלי לרענן.**

זה הרגע שבו כל השרשרת מוכחת: WiFi, שעון, חתימה, שרת, מסד נתונים, ועדכון חי.
הדבר היחיד שעוד לא נבדק הוא ה-USB.

## שלב 6 — הדונגל האמיתי

עכשיו, ורק עכשיו, מחברים חומרה.

### חיווט

```
מחבר USB-A נקבה          ESP32-S3-DevKitC-1
──────────────────       ──────────────────
פין 1  VBUS  (אדום) ───── 5V
פין 2  D−    (לבן)  ───── GPIO19
פין 3  D+    (ירוק) ───── GPIO20
פין 4  GND   (שחור) ───── GND

באזר פסיבי:  + ← GPIO21  ,  − ← GND
```

**חשוב:** מכאן והלאה הטרמינל עובר לשקע ה-`UART`, כי שקע ה-`USB` שייך לסורק.
זה כבר מוגדר בגרסת הבנייה — רק תזכור לחבר את הכבל לשקע הנכון.

### צריבה

```bash
cd firmware && ./dev.sh flash usb
```

חבר את הדונגל למחבר ה-USB-A. **הרחק אותו 10-15 ס"מ מהלוח** בעזרת כבל מאריך —
הוא משדר ב-2.4GHz בדיוק כמו הוויי-פיי של הלוח.

**בדיקה סופית:** קח מוצר מהמטבח, סרוק אותו. ביפ מהסורק, ביפ מהקופסה, והפריט
מופיע בטלפון.

## כשמשהו לא עובד

| מה אתה רואה | מה זה בדרך כלל |
|---|---|
| הנורית מהבהבת כחול ולא מפסיקה | הסיסמה שגויה. אחרי 3 ניסיונות הוא חוזר לעמוד ההגדרה לבד |
| הרשת שלי לא ברשימה | היא 5GHz. חפש את אותה רשת עם סיומת `2.4G`, או פצל אותה בראוטר |
| נורית אדומה מיד אחרי החיבור | לא הצליח לסנכרן שעון או לא מגיע לשרת. בדוק שהשרת עדיין רץ |
| `[time] FAILED` בטרמינל | אין יציאה לאינטרנט מהרשת שבחרת |
| נורית כתומה | סריקות נשמרות מקומית, השרת לא נגיש. הן יישלחו לבד כשיחזור |
| הטרמינל ריק בגרסת usb | הכבל בשקע הלא נכון. בגרסה הזו הטרמינל בשקע `UART` |
| הדונגל לא מזוהה | אין חשמל אליו — ודא שחיברת 5V ל-VBUS. בדוק במודד |
| הסריקה מגיעה חתוכה | הסורק מוגדר לפריסת מקלדת לא אנגלית. הגדר אותו ל-US keyboard |
| `401 bad signature` | השעון של הלוח סטה. יאזן את עצמו בהארט-ביט הבא |
| `externally-managed-environment` | הרצת pip ישירות במקום `firmware/dev.sh pio` |
| `No module named 'intelhex'` | `./.venv-pio/bin/pip install intelhex` |

## חזרה לאפס

לחיצה של 10 שניות על כפתור `BOOT` מוחקת סיסמת WiFi, סוד ותור — והמכשיר חוזר
למצב הגדרה כאילו יצא מהקופסה.

## הערה על שלוש גרסאות הבנייה

| גרסה | מקור הברקוד | פלטפורמה | הטרמינל בשקע |
|---|---|---|---|
| `serial` | הקלדה בטרמינל | Arduino 2.x (יציבה) | `USB` |
| `uart` | מודול סורק טורי | Arduino 2.x (יציבה) | `USB` |
| `usb` | סורק או דונגל USB | Arduino 3.x (קהילתית) | **`UART`** |

גרסת ה-USB בונה מול פלטפורמה אחרת, כי ספריית ה-USB-Host דורשת ESP-IDF 5 שהגרסה
הרשמית של PlatformIO עדיין לא מספקת. שתי הגרסאות האחרות נשארות על היציבה, כך
שתקלה שם לא יכולה להשפיע עליהן.

שלושתן קומפלו ונבדקו. הקושחה תופסת כ-1MB מתוך 4MB ו-14% מה-RAM.

## Bluetooth — נבדק ונשלל

הסורק HBA-W7 מתחבר כמקלדת **Bluetooth קלאסית**, לא BLE. macOS מסווג אותו כך:

```
BARCODE SCANNER    Services: 0x800020 < HID ACL >     ← קלאסי
MX Master 3S       Services: 0x400000 < BLE >          ← BLE
```

`ACL` הוא סוג הקישור של Bluetooth קלאסי. **ל-ESP32-S3 אין רדיו Bluetooth קלאסי
כלל** — רק Bluetooth 5 LE. זו מגבלת סיליקון ואין קושחה שתעקוף אותה.

**המסקנה:** הסורק מתחבר דרך דונגל ה-2.4GHz שלו ל-USB, וזה עובד. Bluetooth ירד
מהשולחן, אלא אם יימצא ברקוד הגדרה שמעביר את הסורק למצב BLE.

כלי האבחון שקבע את זה נשאר ב-`firmware/tools/blescan/` — הוא סורק, מתחבר,
ומדפיס את שירותי ה-GATT של כל מכשיר קרוב. שימושי לכל סורק עתידי שנשקול.

```bash
cd firmware && ./dev.sh pio run -e blescan -t upload -t monitor
```
