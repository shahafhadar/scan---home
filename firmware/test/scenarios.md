# תרחישי כשל — תוכנית בדיקה

הרשימה הזו לא בודקת שהמוצר עובד. היא בודקת מה קורה כשהוא לא.

לכל תרחיש: איך לגרום לו, מה ההתנהגות הנכונה, ואיפה רואים אותה. תרחיש שסומן
✅ בוצע על החומרה הזו והלוג מצוטט. תרחיש שסומן ⬜ עדיין לא.

מה שרואים בכל בדיקה:

```bash
./dev.sh status
```

---

## 1. אתחול והתאוששות

### ✅ 1.1 אתחול רגיל
לחיצה על EN, או ניתוק חשמל וחיבור מחדש.

**נכון:** המכשיר עולה, מדווח את סיבת האתחול, מתחבר, ומגיע ל־Ready.

```
[00:00:00.227][INFO ][boot   ] start: POWERON (boot #3)
```

### ✅ 1.2 אתחול מרחוק
```bash
cd server && npm run ota -- reboot SC-XXXXXXXX
```
**נכון:** תוך דקה — `start: SW`. **לא** נספר ככשל.

```
[00:00:00.251][INFO ][boot   ] start: SW (boot #12)
[00:00:00.252][INFO ][safe   ] planned restart; not counted against this device
```

### ⬜ 1.3 Watchdog
להוסיף `while (1) {}` זמני בתוך `loop()`, לצרוב, ולחכות.

**נכון:** אחרי 30 שניות אתחול, והבוט הבא מדווח `TASK_WDT`.
**קריטי:** אם המכשיר נשאר תקוע — ה־watchdog לא מאכיל נכון, או שמישהו מאכיל
אותו בתוך לולאה חוסמת. זה מבטל את כל התועלת.

### ⬜ 1.4 Brownout
להזין מספק חלש, או לחבר עומס בזמן ריצה.

**נכון:** `start: BROWNOUT` והודעה שמכוונת לספק ולא לקוד.

### ⬜ 1.5 Safe Mode
`nvs` → להעלות ידנית את `safemode/failures` ל־5, או לצרוב קושחה שקורסת ב־setup.

**נכון:** אתחול חמישי עולה עם רשת ועדכונים בלבד, `[SAFE MODE]` ב־status,
והמכשיר עדיין מקבל OTA.

## 2. רשת

### ✅ 2.1 השרת לא זמין
```bash
lsof -ti:4300 | xargs kill
```
**נכון:** סריקות נכנסות לתור, ביפ "queued", בלי אתחול. השרת חוזר → התור מתרוקן.
נבדק: המכשיר המשיך, ה־watchdog של האופס החזיר את השרת תוך 6 שניות.

### ⬜ 2.2 WiFi נופל בזמן פעולה
לכבות את הראוטר, לחכות דקה, להדליק.

**נכון:** חזרה לחיבור עם backoff, **בלי אתחול**, ו־`wifi_reconnects` עולה.

### ⬜ 2.3 יש WiFi, אין אינטרנט
לחסום את היציאה בראוטר, או להפעיל נקודה חמה בלי חיבור.

**נכון:** E002 ולא E001. ההבחנה חשובה: השתיים דורשות פעולה שונה מהמשתמש.
**סטטוס:** מיושם רק חלקית — סעיף 3.4 בתוכנית.

### ⬜ 2.4 DNS לא עונה
להצביע על שם שלא נפתר.

**נכון:** כשל תוך ה־timeout, לא תקיעה, ו־watchdog לא נורה.

### ✅ 2.5 תשובה ענקית
שרת בדיקה שמחזיר `Content-Length` גדול מ־4096.

**נכון:** E018, התשובה לא נקראת, המכשיר ממשיך.
מיושם ב־`Uplink::readBounded`. חשוב לא פחות: תשובה **בלי** אורך מוצהרת
נדחית גם היא, כי `getString()` על תשובה chunked קורא עד סגירת החיבור.

### ⬜ 2.6 תשובה שאינה JSON
שרת שמחזיר HTML או זבל.

**נכון:** E006, בלי קריסה.

## 3. סריקה ותור

### ✅ 3.1 הסורק נשלף
לנתק את הדונגל מהשקע.

**נכון:** אחרי 30 שניות המארח מאתחל את עצמו, עם backoff שמכפיל.

```
[00:00:30.272][WARN ][usb] E010 no scanner for 30s, restarting the host (attempt 1)
[00:01:00.272][WARN ][usb] E010 no scanner for 30s, restarting the host (attempt 2)
[00:02:00.272][WARN ][usb] E010 no scanner for 60s, restarting the host (attempt 3)
[00:04:00.272][WARN ][usb] E010 no scanner for 120s, restarting the host (attempt 4)
```

זו הייתה התקלה הפתוחה: קודם, מארח שלא ספר את הדונגל נשאר שותק לנצח.

### ✅ 3.2 חשמל נופל עם תור מלא
לסרוק חמישה פריטים בלי שרת, לנתק חשמל, לחבר.

**נכון:** `[queue] N scans waiting from before`, הכל נשלח, בלי כפילויות.
נבדק: 5 בתור, 7 סריקות, 7 פריטים ייחודיים.

### ⬜ 3.3 תור מלא
500 סריקות offline.

**נכון:** הישנות ביותר נופלות, `queue_dropped` עולה. **לא** החדשות.

### ⬜ 3.4 רשומה מורעלת
שרת שדוחה ברקוד מסוים תמיד.

**נכון:** אחרי 10 ניסיונות הרשומה עוברת ל־`failed` ויוצאת מהמחזור.

### ⬜ 3.5 קלט שאינו ברקוד
מקלדת רגילה בשקע USB, הקלדת טקסט.

**נכון:** E011, הקלט נדחה בדלת, שום דבר לא מגיע לתור.

## 4. עדכונים

### ✅ 4.1 OTA תקין
```bash
tools/ota-release.sh usb SC-XXXXXXXX
```
**נכון:** הורדה, אימות חתימה, התקנה, אתחול לגרסה החדשה.
נמדד: 1.34MB בשש שניות.

```
[00:05:00.196][INFO ][net] heartbeat carried a command (96 bytes)
[00:05:00.197][INFO ][cmd] server asked for: ota
[00:05:00.267][INFO ][ota] updating to 1.0.2
[00:05:06.385][INFO ][ota] signed image installed; restarting into it
```

### ✅ 4.2 חתימה שגויה
```bash
# לפגום בחתימה של גרסה שפורסמה
./dev.sh psql -c "UPDATE firmware_releases SET signature = '\x00' WHERE version='X'"
```
**נכון:** E016, האימג' נזרק, המכשיר נשאר על הגרסה הישנה.
**זו הבדיקה החשובה ביותר בקובץ.** אם היא נכשלת, כל מי ששולט ב־DNS שולט במכשיר.

```
[00:06:00.107][INFO ][ota ] updating to 1.0.5
[00:06:08.176][ERROR][sig ] E016 signature does not match this image (-0x4e00)
[00:06:08.176][CRIT ][ota ] E016 image discarded: it was not signed by us
```

1.34MB הורדו, גובבו, ונזרקו. המכשיר נשאר על הגרסה שרץ בה.

### ⬜ 4.3 חתימה חסרה
לפרסם בלי `.sig`.

**נכון:** סירוב לפני שההורדה מתחילה בכלל.

### ⬜ 4.4 חשמל נופל באמצע ההורדה
לנתק אחרי כשלוש שניות.

**נכון:** האתחול חוזר לגרסה הישנה. מחיצת A/B — האימג' החדש מעולם לא הפך ל־boot target.

### ⬜ 4.5 קושחה שעולה ולא עובדת
לפרסם אימג' שמצביע על שרת שלא קיים.

**נכון:** עולה, לא מצליח להגיע לשרת, ואחרי 15 דקות **מגלגל את עצמו אחורה**.
**זו הבדיקה שמוכיחה שה־probation אמיתי.** בלי `verifyRollbackLater()` היא
תיכשל בשקט: הליבה של ארדואינו מסמנת כל אימג' כתקין עוד לפני `setup()`.

### ✅ 4.6 עדכון על גבי עדכון
לשלוח OTA בזמן שהאימג' הנוכחי עדיין ב־probation.

**נכון:** סירוב. אחרת מאבדים את העותק הידוע־טוב האחרון.

```
[00:02:00.063][INFO ][cmd ] server asked for: ota
[00:02:00.063][WARN ][ota ] E013 still proving the current image; not updating yet
```

---

### ✅ 4.7 חלון ה־probation נסגר כשצריך
לשלוח OTA תקין ולהמתין.

**נכון:** חמש דקות ושלוש שיחות עם השרת, ואז אישור.

```
[00:00:00.271][INFO ][ota ] running from app1, image is pending-verify
[00:00:00.272][WARN ][ota ] this image is on probation: 900s to prove itself
[00:05:00.294][INFO ][ota ] image confirmed after 300s and 5 exchanges; rollback disarmed
```

**חשוב:** לפני `verifyRollbackLater()` השורה הראשונה אמרה `valid` והשנייה לא
הופיעה בכלל. אם זה מה שרואים — ה־rollback מנוטרל וכל שאר הבדיקה חסרת ערך.

### ✅ 4.8 אתחול יזום לא נספר ככשל
```bash
cd server && npm run ota -- reboot SC-XXXXXXXX
```
**נכון:** `planned restart; not counted against this device`. בלי זה, חמישה
עדכונים ברצף מכניסים מכשיר בריא ל־safe mode.

## 5. אחסון וזהות

### ✅ 5.1 Factory reset
החזקת BOOT עשר שניות.

**נכון:** הכל נמחק, המכשיר חוזר ל־captive portal, והשרת מנפיק סוד חדש.

### ✅ 5.4 בדיקה עצמית באתחול
עולה מעצמה בכל boot.

**נכון:** `[self] all checks passed`. כשל מדווח בשם: `SELF TEST FAILED: nvs,fs`.
בדיקה שנכשלה כאן מצילה שעה של חיפוש במקום הלא נכון.

### ✅ 5.5 Snapshot אבחון
```bash
cd server && npm run ota -- diag SC-XXXXXXXX
cd server && npm run ota -- show SC-XXXXXXXX
```
**נכון:** מסמך JSON עם מחיצות, רשת, אחסון, שגיאות לפי קוד, והקבועים שהבנייה
הזו הודרה איתם. האחרון חשוב יותר משהוא נשמע: "התור מחזיק 500" זו עובדה על
הבנייה שמולך, לא על הצי.

### ⬜ 5.2 NVS פגום
למחוק את מחיצת ה־nvs.

**נכון:** ברירות מחדל, E014, והמכשיר עדיין עולה.

### ⬜ 5.3 LittleFS פגום
לכתוב זבל למחיצת הקבצים.

**נכון:** פרמוט תוך תקרת זמן, האכלת watchdog, E007 אם נכשל — והמכשיר רץ בלי
תור במקום להיראות תקוע.

## 6. יציבות לאורך זמן

### ⬜ 6.1 Soak
להשאיר מחובר שבוע.

```bash
./dev.sh status   # "memory trend (last 24h)"
```

**נכון:** `min_heap` מתייצב. ירידה מונוטונית לאורך ימים היא דליפה.
**נמדד עד כה:** יציב על ~201KB לאורך שעה, `min_heap` יורד רק בדקה הראשונה
ואז נעצר — התייצבות, לא דליפה.

### ⬜ 6.2 עומס סריקות
מאתיים סריקות ברצף.

**נכון:** בלי ירידת heap, בלי סריקות אבודות, בלי כפילויות.
